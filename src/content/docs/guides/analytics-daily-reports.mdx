FormMail Hub provides built-in email tracking, delivery analytics, and automated daily reporting to give administrators clear visibility into operational notifications, customer auto-responders, and broadcast campaign performance.

All email transactions are tracked per form on a daily basis across three distinct execution modes. Test form submission triggers on our [Live Demo Form](https://docs.google.com/forms/d/e/1FAIpQLSc2lkYREd5ePz521uYfBDeumOOoPKeBP87i1aSpwokHdFMIHw/viewform) or install the add-on directly from the [Google Workspace Marketplace Listing](https://workspace.google.com/marketplace/app/formmail_hub/409227874327).

## 1. Prerequisites & UI Access Requirements

To access the Analytics dashboard tab and view detailed email metrics:

- **Custom SMTP Requirement & UI Lock State:** Admins **MUST** configure and test custom SMTP settings before unlocking Templates, Rules, Campaigns, or Analytics. Until custom SMTP is active, these feature tabs remain strictly locked in the UI.
- **Built-in System SMTP Scope:** Built-in System SMTP is **STRICTLY** restricted to sending system alerts (submission notifications, daily activity reports, and SMTP connection error alerts) to the Form Admin and selected Team Members. System SMTP **CANNOT** be used for custom templates, rule-based notifications, or respondent auto-responders.

## 2. Multi-Mode Metric Tracking Engine

FormMail Hub captures every email transaction—categorized into three core delivery metrics—and aggregates them per connected Google Form™ on a daily basis.

```
+-----------------------------------------------------------------------------------+
|                        FORMMAIL HUB TRACKING ENGINE                               |
+-----------------------------------------------------------------------------------+
                                  |
          +-----------------------+-----------------------+
          |                                               |
          v                                               v
+-----------------------------------+           +-----------------------------------+
|       METRICS TRACKED             |           |       EXECUTION MODES             |
+-----------------------------------+           +-----------------------------------+
| - emails_sent   (Delivered count) |           | 1. system: Operational alerts,   |
| - emails_failed (Terminal errors) |           |    daily reports, SMTP errors     |
| - emails_opened (Tracking pixel)  |           | 2. automation: Auto-responders &  |
|                                   |           |    submission-triggered rules     |
|                                   |           | 3. campaign: Bulk emails from     |
|                                   |           |    Google Sheets add-on           |
+-----------------------------------+           +-----------------------------------+
```

### Metrics Tracked per Form
- **`emails_sent`**: Total messages successfully delivered to target mail transfer agents and custom SMTP servers.
- **`emails_failed`**: Total permanent delivery failures, unresolvable connection errors, or authentication failures recorded strictly when all retry attempts have been exhausted.
- **`emails_opened`**: Total email opens recorded via privacy-compliant tracking pixels.

> **Retry & Failure Logging Mechanism:** If an email encounters a temporary network issue, the cloud engine retries the message automatically. The `emails_failed` metric is incremented **strictly on the final attempt** if all retry attempts fail, preventing temporary retries from distorting daily statistics.

### 3 Execution Modes
1. **`system`**: Automated operational alerts, daily summary reports, and SMTP connection error notifications dispatched via built-in System SMTP.
2. **`automation`**: Submission-triggered auto-responders, multi-condition rule emails, and staff ticket notifications dispatched via custom SMTP.
3. **`campaign`**: Proactive bulk marketing and informational broadcasts dispatched from the Google Sheets™ add-on management client.

## 4. Per-Form Daily Summary Reports & Timezone Support

To keep administrators informed without requiring manual dashboard logins, FormMail Hub automatically generates and delivers daily summary emails.

```
[ Daily Midnight Boundary (00:00 in Form's Configured Timezone) ]
                              |
                              v
   [ Cloud Engine Normalizes Timezone & Aggregates Daily Metrics ]
                              |
                              v
 [ System SMTP Dispatches Daily Summary Report Email to Form Admin ]
                              |
       +----------------------+----------------------+
       |                                             |
       v                                             v
[ Admin Reviews Daily Metrics ]        [ Form-Specific Unsubscribe Link ]
                                                     |
                                                     v
                                  [ Opts Out Strictly for That Form ]
                                  [ Other Active Forms Continue Reporting ]
```

### Automated Dispatch Mechanics
- **Schedule:** At the start of a new day (**00:00 according to each form's configured timezone**), the system automatically generates and dispatches a Daily Summary Report email via System SMTP to the Form Admin for each active Form.
- **Content:** Comprehensive breakdown of the previous day's `emails_sent`, `emails_failed`, and `emails_opened`, categorized across `system`, `automation`, and `campaign` execution modes.
- **Quota-Free Delivery:** Delivered via built-in System SMTP, ensuring that daily reports consume 0% of your custom SMTP sending quota.

### Timezone Handling
FormMail Hub features automated timezone normalization ensuring accurate midnight report scheduling across global regions:
- **Canonical Timezone Names:** Full support for canonical timezones (e.g., `America/New_York`, `Europe/London`, `Asia/Ho_Chi_Minh`, `Asia/Tokyo`).
- **Offset Formats:** Accepts standard offset notations such as `+07:00`, `-05:00`, `GMT+7`, or `UTC+7`.

### Granular Per-Form Unsubscribe Control
Admins managing multiple forms can independently opt out of daily reports for high-volume or non-critical forms without disabling reports globally:
- **Embedded Unsubscribe Link:** Every daily report includes a dedicated form-specific unsubscribe link.
- **Scope Isolation:** Unsubscribing stops daily reports **strictly for that specific form**, keeping daily summary reports active for all other forms.

## 5. Granular Opt-Out & Compliance Matrix

FormMail Hub manages unsubscribes across three strict, independent scopes:

| Scope Level | Target Audience | Trigger Context | System Action |
| :--- | :--- | :--- | :--- |
| **Form-Specific Respondent Unsubscribe** | Form Respondents | `{Unsubscribe Link}` clicked in Auto-responders or Campaigns | Unsubscribes respondent's email address strictly from future emails related to that specific Form. |
| **Form-Specific System Daily Report Unsubscribe** | Form Admin / Team | Unsubscribe link in Daily Summary Report email | Stops daily summary report emails strictly for that specific Form. |
| **User-Level SMTP Error Alert Unsubscribe** | Form Admin | Unsubscribe link in SMTP failure warning email | Stops SMTP connection failure notifications across all forms managed by that user account. |
