## Architectural Breakdown: 4 Ingestion Bridges & 1 Cloud Platform

FormMail Hub decouples event capture in Google Workspace from backend delivery and state execution:

```
+-----------------------------------------------------------------------------------+
|                        DATA INGESTION BRIDGES (GOOGLE ADD-ONS)                     |
|  +---------------------------+  +-------------------+  +-----------------------+  |
|  | Form Confirmation Emails  |  |   Form to Email   |  | Form Notifications    |  |
|  |     (Forms Add-on)        |  |  (Forms Add-on)   |  |    SMTP (Forms)       |  |
|  +---------------------------+  +-------------------+  +-----------------------+  |
|  +-----------------------------------------------------------------------------+  |
|  |                 FormMail Hub for Google Sheets™ (Add-on)                    |  |
|  |                (Primary Management Client / Campaign Launchpad)            |  |
|  +-----------------------------------------------------------------------------+  |
+------------------------------------------+----------------------------------------+
                                           | Pushes Submission Events & Config Data
                                           v
+-----------------------------------------------------------------------------------+
|                   INDEPENDENT CLOUD PLATFORM ENGINE (EXTERNAL)                    |
|       (High-Performance Event Processing, Rule Evaluation & SMTP Engine)          |
+-----------------------------------------------------------------------------------+
```

### 1. Ingestion Bridges & Scaling
- **3 Google Forms Entry Add-ons:** *Form Confirmation Emails*, *Form to Email*, and *Form Notifications SMTP* act strictly as data ingestion bridges pushing submission events to the cloud platform engine.
- **1 Google Sheets Management Client:** The *FormMail Hub* Google Sheets add-on acts as the primary full-featured management client. A single spreadsheet can host multiple Form Responses tabs, consuming only **1 connection slot** while providing the interface to launch bulk email **Campaigns**.

### 2. Dual Delivery Routing Architecture
- **Built-in System SMTP:** Strictly restricted to sending internal system alerts (submission notifications, daily activity reports, and SMTP connection error alerts) to the Form Admin and selected Team Members without consuming your personal SMTP quota.
- **Custom SMTP Relay:** Mandatory for custom email templates, conditional rules, respondent auto-responders, and bulk campaigns. Admins **MUST** configure and test custom SMTP to unlock the UI tabs (*Templates*, *Rules*, *Campaigns*, and *Analytics*).

### 3. Stateful QR Attendance Engine
- **Atomic Concurrency & 30-Day Rolling TTL:** Scans and verification clicks are processed under Redis key `checkin:{form_id}:{refCode}`, rejecting duplicate check-ins (`409 Conflict`) if already `IN`, and refreshing TTL to 30 days on every state transition.
- **Camera & Camera-Free Verification:** Staff can scan visual QR codes with their authorized mobile camera or click direct manual verification links (`{Verify Link}` / `/qr-verify?t=...`) inside notification emails.
- **7-Day Browser Authorization:** Personalized scanner links set a 7-day cryptographically signed authorization cookie (`scan_perms`) on the user's browser.

### 4. Multi-Mode Metric Tracking & Daily Reports
- **Multi-Mode Metrics:** Daily logging of `emails_sent`, `emails_failed`, and `emails_opened` strictly categorized across `system`, `automation`, and `campaign` execution modes.
- **Midnight Summary Reports:** Automated daily reports dispatched at 00:00 (form timezone) via System SMTP to the Form Admin with per-form opt-out capability.

## Verified Dynamic Tags Reference

Dynamic tags use single-pass scanning supporting `{Tag}`, `{{Tag}}`, and `${Tag}` enclosure formats:

| Dynamic Tag | Purpose & Output | Audience Scope |
| :--- | :--- | :--- |
| `{Question Title}` | Dynamically retrieves the submitted response for any form question field title. | All Templates |
| `{Form title}` | The official title of the connected Google Form™. | All Templates |
| `{All fields}` | Formatted summary table of all form questions and submitted answers. | All Templates |
| `{Linked form}` | Direct URL link to the live Google Form™. | All Templates |
| `{Unsubscribe link}` | Form-specific automated opt-out link for compliance. | Respondent & Campaign Emails |
| `{QR Code}` | Stateless QR code ticket image (HMAC-SHA256 signed) + manual verification link (`/qr-verify?t=...`). | Respondent Tickets, Self-Attendance & Staff Alerts |
| `{Verify Link}` | Direct clickable verification URL (`/qr-verify?t=...`) for instant camera-free verification on PC/mobile. | Respondent Tickets, Self-Attendance & Staff Alerts |
| `{Check-in Scanner}` | Personalized, HMAC-SHA256 signed zero-login staff link (`checkin` mode, 7-day validity). | Staff / Team Emails Only |
| `{Check-out Scanner}` | Personalized, HMAC-SHA256 signed zero-login staff link (`checkout` mode, 7-day validity). | Staff / Team Emails Only |
| `{Full Scanner}` | Personalized, HMAC-SHA256 signed zero-login link (`both` mode, 7-day validity). | Staff Emails & Submitter Self-Attendance |

## Granular Opt-Out & Compliance Scopes

FormMail Hub manages unsubscribes across 3 strict scopes:
1. **Form-Specific Respondent Unsubscribe:** Clicking `{Unsubscribe link}` in custom templates or campaigns unsubscribes the respondent strictly from future emails related to that specific Form.
2. **Form-Specific System Daily Report Unsubscribe:** Unsubscribes Admins or Team Members from daily summary reports for that specific Form only.
3. **User-Level SMTP Error Alert Unsubscribe:** Stops SMTP failure notification emails across all forms managed by that user account.
